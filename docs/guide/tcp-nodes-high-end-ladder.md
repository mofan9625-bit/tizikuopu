在当下梯子网络技术的宣传中，基于 UDP 协议的 **Hysteria 2、TUIC** 几乎成了“速度与抗弱网”的代名词，很多人盲目认为“协议越新越好、UDP 绝对碾压 TCP”。

## 一、TCP 节点 vs UDP 节点：生产力场景下的底层技术对决

传输控制协议（TCP）与用户数据报协议（UDP）是互联网传输层的两大支柱，在代理网络中有截然不同的表现特征：

| 评估维度 | 高端专线 TCP 节点（Shadowsocks / VLESS TCP） | 现代公网 UDP 节点（Hysteria 2 / TUIC） |
| :--- | :--- | :--- |
| **连接机制** | 面向连接（严格三次握手 + 序列号确认 + 滑动窗口） | 无连接（尽力而为传输 + 暴力快速重传机制） |
| **数据完整性与有序性**| **100% 绝对可靠有序**（不允许哪怕 1 个字节错位） | 依赖应用层重组包（容易出现数据乱序与瞬时丢包） |
| **国内运营商 QoS 策略**| **运营商友好**（与正常网页访问一致，极少恶意阻断）| **高危严管**（许多省份宽带常态化对境外 UDP 限速或黑洞）|
| **长连接持续稳定性** | **极高**（内网专线保障下，SSH 可常挂数天不掉线） | 一般（移动切网或 UDP 阻断时容易瞬时中断心跳） |
| **典型适用场景** | **极客开发、Git 仓库协同、SSH 终端、金融 API 交易** | **劣质校园网、高峰期公网看视频、海量大流量下载** |

```text
[TCP 专线长连接保障机制]
极客终端 ──[SSH / Git / API 交互]──> [本地客户端] ──[TCP 强可靠连接]──> [境内 BGP -> IPLC 纯内网物理光纤] ──> 海外服务器
* 链路特征：运营商内网光缆直通，RTT 20ms，Jitter < 1ms，TCP 滑动窗口永不触发拥塞退避，终端丝滑如本地。
```

## 二、为什么运营商骨干网对境外 UDP 容易触发激进阻断？

很多用户不解：为什么新兴的 UDP 协议在某些宽带下会突然断流？
1. **防止 UDP 反射放大攻击（DDoS 防护机制）**：
   - UDP 报文无握手、允许伪造源 IP，是全球黑客发起大规模分布式拒绝服务攻击的主要手段。中国电信、中国联通与中国移动的省级骨干网出口部署了极度严格的异常 UDP 流量监控阈值。
2. **激进的 UDP QoS 丢包惩罚**：
   - 当公网国际出口拥塞时，运营商首选放弃的往往就是无连接的 UDP 流量，甚至将境外未知端口的 UDP 丢包率直接拉高到 50%~80%；
3. **TCP 拥有最广泛的穿透性与合规性**：
   - 商业企业内网与公共 Wi-Fi 通常只放行 80、443 等标准 TCP 端口，直接封杀全部非标准 UDP 流量。因此，**无论是从穿透性还是长连接可靠性来看，高质量 TCP 节点都是永不过期的主力军**。

## 四、极客客户端调优：Clash / Sing-box 优化 TCP 长连接实操

为了让 TCP 节点发挥最强生产力性能，建议在客户端进行如下高阶微调：

1. **开启 TCP Fast Open（TFO，TCP 快速打开）**：
   - 在客户端配置中开启 `tcp-fast-open: true`，在后续请求中省去标准三次握手的往返等待，实现首包极速发射，使网页与 API 响应提速 30% 以上。
2. **启用 Keep-Alive（长连接保活心跳）**：
   - 针对 SSH 远程终端用户，在 `~/.ssh/config` 中增加：
     ```text
     Host *
         ServerAliveInterval 30
         ServerAliveCountMax 3
     ```
     让客户端每隔 30 秒自动发送空保活包，彻底避免中间 NAT 超时断开。
3. **分流策略：开发与跨境业务互不干扰**：
   - 研发人员可参考 [《2026 高质量外贸与出海线路梯子选型指南》](/guide/foreign-trade-cross-border-ladder)，将代码托管平台（GitHub/GitLab）、AI 编程辅助（Cursor/Copilot）精准路由至 TCP 专线，国内 npm/pip 镜像源锁定 DIRECT 本地直连。

## 💡 常见疑问：TCP 专线节点实操答疑

### Q1: 为什么我的 TCP 节点 Ping 延迟很低，但测速时起步速度不如 Hysteria 2 快？
**答**：这是 TCP 拥塞控制算法（如 BBR、CUBIC）的“慢启动机制（Slow Start）”导致的正常现象。TCP 为了保护网络不发生瞬间拥堵，起步发送速率较低，逐步倍增；而 UDP 协议是一上来就全速发包。在专线环境下，TCP 只需 1~2 秒就能拉满千兆带宽，且后续传输极为平稳，绝不发生中途断流。

### Q2: 我使用 SSH 连海外服务器经常过一会儿就卡死，是梯子的问题吗？
**答**：绝大多数是因为使用了劣质公网梯子或开启了不稳定的 UDP 节点。公网中转节点在路由重敛或 NAT 超时后会直接丢弃连接状态，导致终端假死；换用 IPLC/IEPL 物理专线的 TCP 节点，并配合 `ServerAliveInterval` 保活参数，即可彻底根治。

### Q3: 手机端日常挂后台，TCP 节点和 UDP 节点哪个更省电？
**答**：**TCP 节点（尤其是基于 Shadowsocks 的专线 TCP 节点）明显更省电**。现代手机芯片对标准 TCP/TLS 和 AES 加解密有硬件级硬件加速，无需像 Hysteria 2 那样频繁在后台暴力发包重传，长挂后台发热量极低。更多协议功耗对比详见 [《主流梯子协议全解密》](/wiki/proxy-protocols-vless-trojan-hysteria)。
