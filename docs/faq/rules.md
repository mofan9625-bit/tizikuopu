# 客户端报错、订阅同步与规则分流 FAQ 知识库 (21-40题)

本篇聚焦客户端运行排错、订阅同步异常、TUN 模式与智能分流规则的 20 个核心解答。

---

### 21. 订阅链接更新一直提示“Timeout”或“网络请求失败”该如何解决？
- **【核心痛点/成因分析】**：订阅服务器域名可能被本地 DNS 污染，或本地代理客户端未开启直连更新，导致请求陷入死循环。
- **【排障步骤与解决方案】**：
  1. 开启“系统代理”后重试更新，或复制订阅 URL 在浏览器中直接打开校验。
  2. 尝试替换订阅域名为备用 CDN 节点域名。
- **【极客选型建议】**：选择提供多域名冗余订阅及自动 Subconverter 备用转换链接的服务商。

---

### 22. 提示“Format error”或“Invalid YAML”配置文件解析报错的原因是什么？
- **【核心痛点/成因分析】**：YAML 语法对空格和缩进极度敏感。使用了 Tab 制表符、中文特殊符号或服务端返回了 502/404 错误网页 html 均会导致该报错。
- **【排障步骤与解决方案】**：用文本编辑器打开配置文件，查看开头是否为 HTML 网页源码，并使用 YAML 在线校验语法格式。
- **【极客选型建议】**：客户端使用 Clash Verge Rev 或 Sing-box，其内置语法错误智能纠错与预览功能。

---

### 23. 为什么修改了系统时间后，所有节点都会出现 TLS 握手失败？
- **【核心痛点/成因分析】**：加密协议（如 TLS、Hysteria 2、VMess）需要本地时间与服务器时间同步。若时间差超过 90 秒，TLS 证书校验将自动判定失效。
- **【排障步骤与解决方案】**：打开系统设置，开启“自动设置时间”与“与 NTP 时间服务器同步”。
- **【极客选型建议】**：保持本地设备 NTP 自动同步，避免由于时间偏差引发加密握手失败。

---

### 24. 开启代理后国内外卖、打车和网银 App 定位跑到海外甚至被风控怎么办？
- **【核心痛点/成因分析】**：代理软件处于“全局模式 (Global)”，导致所有本地应用请求均通过海外 IP 出站，触发风控警报。
- **【排障步骤与解决方案】**：切换客户端路由模式至“规则模式 (Rule)”，并确认规则库中包含 `GEOIP,CN,DIRECT`。
- **【极客选型建议】**：使用基于 GeoIP 与 GeoSite 数据库更新频繁的智能规则集，确保国内 App 精确走直连。

---

### 25. 全局代理（Global）与规则分流（Rule）有什么区别？为什么日常推荐规则模式？
- **【核心痛点/成因分析】**：全局模式将所有流量强制走代理，白白浪费专线流量且易引发本地 App 异地风控；规则模式则按域名与 IP 智能按需分配。
- **【排障步骤与解决方案】**：日常使用一律保持为规则模式（Rule），仅在特定未收录的海外小众网站打不开时临时切换全局。
- **【极客选型建议】**：采用现代规则集技术，实现国内直连、海外代理、AI/流媒体专项分流。

---

### 26. 什么是 TUN 虚拟网卡模式？它与常规系统代理（System Proxy）有何优劣？
- **【核心痛点/成因分析】**：系统代理仅作用于遵循 HTTP/HTTPS 代理协议的软件；TUN 模式在系统层建立虚拟网卡，可透明接管所有 UWP 应用、游戏及终端流量。
- **【排障步骤与解决方案】**：在 Clash Verge 或 Sing-box 中一键开启 `TUN Mode` 并安装驱动。
- **【极客选型建议】**：需要全局游戏加速、终端开发或 UWP 软件代理的用户，强烈建议启用 TUN 模式。

---

### 27. 为什么在电脑端开了代理后，终端命令行（Terminal/CMD）依然无法联网？
- **【核心痛点/成因分析】**：Windows CMD/PowerShell 与 Linux 终端默认不继承系统 HTTP 代理设置。
- **【排障步骤与解决方案】**：在终端手动执行：`$env:HTTP_PROXY="http://127.0.0.1:7890"; $env:HTTPS_PROXY="http://127.0.0.1:7890"`。
- **【极客选型建议】**：直接开启客户端的 TUN 模式，免去终端手动配置环境变量的烦恼。

---

### 28. 如何配置自定义规则集（Rule Provider），让特定工作域名强制走指定直连或节点？
- **【核心痛点/成因分析】**：内置规则可能未覆盖公司内部域名或特定工作站点，导致流量路由非预期。
- **【排障步骤与解决方案】**：在配置文件 `rules:` 首行添加自定义规则：`- DOMAIN-SUFFIX,company.com,DIRECT`。
- **【极客选型建议】**：善用自定分流规则优先级（顶部优先匹配机制），提升工作效率。

---

### 29. 为什么手机锁屏后后台节点经常被系统杀进程断连？iOS 与安卓后台保活技巧。
- **【核心痛点/成因分析】**：移动操作系统为了省电，会在锁屏后强制清理后台高内存与高 CPU 消耗的 VPN 进程。
- **【排障步骤与解决方案】**：
  1. 安卓端将客户端加入内存清理白名单并开启“自启动”。
  2. iOS 端确保使用轻量客户端（如 Sing-box 或 Shadowrocket）。
- **【极客选型建议】**：选用内存开销低至 `<20MB` 的 Sing-box，极大降低被系统杀后台的概率。

---

### 30. 客户端提示“DNS 泄漏（DNS Leak）”是什么意思？它会带来哪些隐私风险？
- **【核心痛点/成因分析】**：开启代理后，访问海外网站的 DNS 查询请求却依然泄露给了本地运营商 DNS 伺服器，可能导致访问记录被监听。
- **【排障步骤与解决方案】**：访问 `dnsleaktest.com` 展开测试，确保解析结果中不包含本地运营商 IP。
- **【极客选型建议】**：配置 Fake-IP 模式并开启 DoH 加密 DNS 伺服器，彻底杜绝 DNS 泄漏。

---

### 31. 如何配置 DNS 分流，让国内域名走本地运营商解析、海外域名走防污染解析？
- **【核心痛点/成因分析】**：单一度 DNS 会导致国内域名解析到海外 CDN（速度变慢），或海外域名解析被污染（打不开）。
- **【排障步骤与解决方案】**：在 `dns:` 配置中设置 `nameserver` 走 223.5.5.5，`fallback` 走 1.1.1.1。
- **【极客选型建议】**：采用现代配置文件提供的标准 DNS 分流模板。

---

### 32. 为什么同一份订阅在 Clash 上好用，导入 Sing-box 或 Loon 却无法识别？
- **【核心痛点/成因分析】**：不同客户端内核对配置文件的语法（YAML 与 JSON）、字段名称及协议支持存在结构差异。
- **【排障步骤与解决方案】**：使用安全的 Subconverter 转换工具将原始订阅转换为目标客户端对应的协议语法。
- **【极客选型建议】**：优先选择直接提供原厂多客户端订阅格式的服务商。

---

### 33. 什么是 GeoIP 与 GeoSite 数据库？它们在精准分流中起到了什么作用？
- **【核心痛点/成因分析】**：GeoIP 是根据 IP 归属地分类的数据库，GeoSite 是按域名功能分类的数据库。它们是实现自动分流的基础引擎。
- **【排障步骤与解决方案】**：定期在客户端设置中更新 `geoip.dat` 与 `geosite.dat` 规则库。
- **【极客选型建议】**：保持分流数据库为最新版本，获得最精准的分流体验。

---

### 34. 客户端日志里频繁刷“Handshake timeout”是节点被封还是配置错误？
- **【核心痛点/成因分析】**：Handshake timeout 意味着客户端发送加密握手包后在规定时间内未收到回包，可能由网络高丢包或节点 IP 被墙引发。
- **【排障步骤与解决方案】**：使用 TCP Ping 测量节点 IP 与端口，若端口不通则说明节点失效，需更新订阅。
- **【极客选型建议】**：选择具备多节点自动健康检测（url-test）与自动故障切线功能的服务商。

---

### 35. 为什么升级客户端内核后，旧的配置文件突然无法启动服务？
- **【核心痛点/成因分析】**：新版内核（如 Mihomo / Sing-box 最新版）可能废弃了旧版废弃字段或修改了基础语法规则。
- **【排障步骤与解决方案】**：查看客户端控制台日志（Logs），找到具体报错行号并修改废弃字段。
- **【极客选型建议】**：关注官方 Release 文档中的 Break Changes 迁移提示。

---

### 36. 怎么配置 Fallback（自动故障转移）策略组，实现主节点掉线时秒级切备用？
- **【核心痛点/成因分析】**：单节点可能因临时维护失效，缺乏自动切线机制会导致网络中断。
- **【排障步骤与解决方案】**：在策略组中配置 `type: fallback`，设置 `health-check` 探针时间为 `60秒`。
- **【极客选型建议】**：在客户端中挂载 Fallback 故障切线策略，保障体验无缝连贯。

---

### 37. 什么是 Mixed-port 混合端口？如何在一个端口同时处理 HTTP 和 SOCKS5 请求？
- **【核心痛点/成因分析】**：传统客户端分别开 7890(HTTP) 和 7891(SOCKS5) 两个端口，配置复杂；混合端口可自动识别入站协议类型。
- **【排障步骤与解决方案】**：在配置文件中设置 `mixed-port: 7890`，合并原有双端口。
- **【极客选型建议】**：统一使用 mixed-port 配置，简化本地软件代理设置。

---

### 38. 为什么使用订阅转换工具可能会导致订阅 Token 泄露？自建转换的必要性。
- **【核心痛点/成因分析】**：第三方公共订阅转换服务商有可能在后端服务器日志中记录用户的完整订阅 URL 及 Token 密钥。
- **【排障步骤与解决方案】**：避免使用未知的免费转换 API，或使用 Docker 在本地/私有 VPS 上自建 Subconverter。
- **【极客选型建议】**：重视账号安全，优先使用官方原生订阅。

---

### 39. 电脑休眠唤醒后为什么经常出现“代理已连接但无法加载网页”的假死状态？
- **【核心痛点/成因分析】**：休眠时网络断开，唤醒后虚拟网卡或 TCP Socket 连接未及时重置更新。
- **【排障步骤与解决方案】**：在客户端设置中开启“唤醒后自动重启服务”或手动开关一次系统代理。
- **【极客选型建议】**：使用支持休眠自动健康重置的现代化图形客户端。

---

### 40. 为什么 Telegram 语音通话总是显示“正在连接”？UDP 转发未开启的排查方法。
- **【核心痛点/成因分析】**：Telegram 语音通话基于 VoIP UDP 协议传输。若代理节点或客户端未开启 UDP 转发，将无法建立通话。
- **【排障步骤与解决方案】**：在客户端节点配置中确认开启 `udp: true`，并在软件设置中开启 UDP Relay。
- **【极客选型建议】**：实时通讯高频用户务必选用全节点支持 FullCone UDP 转发的服务商。
